# Plan: Autentikasi Pengguna & Manajemen User

## Ringkasan

Menambahkan sistem autentikasi pada streaming viewer (`/`) agar pengguna harus login terlebih dahulu. Admin dapat membuat/mengelola pengguna melalui dashboard admin. Penyimpanan user menggunakan JSON file (tanpa database eksternal).

## Arsitektur Auth

```
Browser (React) → POST /api/auth/login → Server hash password → Set cookie → Redirect ke /
Browser (React) → GET /api/auth/me (cookie) → Server validate session → Return user info
Browser (React) → GET /api/streams (cookie) → Auth middleware → Return streams
```

- **Password hashing**: `crypto.pbkdf2Sync` (Node.js built-in, 100k iterations, SHA-256)
- **Session**: Token HMAC-based di httpOnly cookie (`session_token`)
- **Storage**: JSON file `packages/server/data/users.json` untuk persistensi user
- **Session store**: In-memory Map (hilang saat server restart, user harus login ulang)

## File yang Diubah/Dibuat

### 1. `packages/shared/src/index.ts` — Tambahkan tipe User

Tambahkan interface `User` dan `UserProfile` (tanpa password hash).

### 2. `packages/server/data/users.json` — Baru

File JSON untuk menyimpan data user. Default admin dibuat otomatis jika kosong.

### 3. `packages/server/src/index.ts` — Tambahkan auth & user management

Bagian baru yang ditambahkan:
- **Crypto helpers**: `hashPassword()`, `verifyPassword()`, `createSessionToken()`, `validateSessionToken()`
- **User storage**: `loadUsers()`, `saveUsers()`, create default admin
- **Session Map**: `sessions: Map<string, { userId, expiresAt }>`
- **Middleware**: `requireAuth`, `requireAdmin`
- **Auth routes**:
  - `POST /api/auth/login` — login, set cookie
  - `POST /api/auth/logout` — clear cookie
  - `GET /api/auth/me` — return current user
- **User CRUD routes** (admin only):
  - `GET /api/users` — list users
  - `POST /api/users` — create user
  - `PUT /api/users/:id` — update user
  - `DELETE /api/users/:id` — delete user
- **Protect**: `GET /api/streams` dan `GET /api/streams/:key` dengan `requireAuth`
- **SPA fallback**: Tetap tanpa auth (serve HTML shell)

### 4. `packages/client/src/components/AuthContext.tsx` — Baru

React context yang menyediakan:
- `user: UserProfile | null` — data user login
- `loading: boolean` — status pengecekan auth awal
- `login(username, password)` — fungsi login
- `logout()` — fungsi logout
- Cek `/api/auth/me` saat mount untuk restore session

### 5. `packages/client/src/components/LoginPage.tsx` — Baru

Halaman login dengan:
- Form username/email + password
- Tombol "Masuk"
- Error message "Username atau password salah"
- Loading state saat submit
- Desain dark theme konsisten dengan viewer

### 6. `packages/client/src/components/UserManagement.tsx` — Baru

Panel manajemen user di admin dashboard:
- Tabel user (username, email, role, tanggal dibuat)
- Tombol "Tambah Pengguna" → form inline/modal
- Edit per baris → form pre-filled
- Delete per baris → konfirmasi
- Label Indonesia: "Pengguna", "Tambah Pengguna", "Edit Pengguna", "Hapus Pengguna"

### 7. `packages/client/src/App.tsx` — Modifikasi routing

- Bungkus dengan `AuthProvider`
- Tambah route `/login` → `LoginPage`
- Viewer (`/`) diproteksi: jika belum login, tampilkan `LoginPage`
- Admin (`/admin`) tetap bisa diakses (auth check di client-side)

### 8. `packages/client/src/components/AdminDashboard.tsx` — Modifikasi

- Tambah nav "Pengguna" di sidebar
- Sub-route `/admin/users` via `usePathname()` (bukan router library)
- Conditional rendering: Dashboard stats vs User Management
- Tambah tombol "Keluar" di sidebar footer
